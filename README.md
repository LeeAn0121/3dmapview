# Floor Atlas

현장별 층별 안내도와 단말 목록을 연결하는 웹 뷰어입니다. 공개 안내도를 층별로 쌓아 표시하고, 장소 클릭 시 평면·입체 보기에서 해당 영역으로 이동합니다.

공개 사이트: <https://leean0121.github.io/3dmapview/>

기본 화면에는 **엑셀에 실제 설치 항목이 있는 건물·층만** 표시합니다. 공개 안내도에 5층이 있더라도 설치 목록에 없으면 기본 표시에서 제외합니다. 전체 안내도는 `전체 병원 안내도 보기`를 선택했을 때만 표시합니다. 공개 장소는 실제 단말이나 설치 대수로 만들지 않습니다.

## 원본 안내도 기반 장소 연결

- **현재 표시하는 이미지**에서 읽은 글자와 사용자가 등록한 영역만 사용합니다. 다른 부서의 강조 이미지에서 가져온 좌표를 일반 안내도 위에 겹치지 않습니다. 이미지의 SHA-256 식별자가 다르면 좌표를 재사용하지 않습니다.
- 엑셀의 건물·층을 먼저 연결하고, 같은 층에서 명칭·방 번호가 명확하게 일치할 때 장소를 연결합니다. 101호와 102호를 구분하며, 동명 장소·복합 부서·낮은 OCR 신뢰도·유사명은 자동 확정하지 않습니다.
- **장소 연결과 실제 단말 설치 위치는 별개입니다.** 자동 매칭으로 설치 지점 핀을 만들지 않습니다. 실제 지점은 현장에서 확인하고 직접 지정합니다.
- 검토 화면에서 후보를 미리 보고 연결할 수 있습니다. 동일한 설치 장소명에 적용할 규칙을 저장하면 이 현장·층·원본 이미지에 한해 재사용합니다. 병원 전용 별칭을 다른 현장에 강제로 적용하지 않습니다.
- OCR 이름·방 번호·현장 별칭을 수정하거나 `장소 영역 추가`로 실제 영역을 드래그해 등록할 수 있습니다. 설치 장소가 바뀐 새 엑셀에서는 이전 장소의 확인 결과와 설치 좌표를 지웁니다.
- 이전 버전의 자동 대표점은 마이그레이션 때 제거합니다. 직접 지정한 설치 지점은 보존하되, 안내도 이미지를 교체하면 이전 위치를 재확인하도록 해제합니다.
- 장소 목록, 안내도 영역 또는 단말을 선택하면 해당 층을 열고 선택 장소를 중심으로 이동합니다. 입체 보기에서는 선택한 층을 앞으로 꺼내고 나머지 층을 흐리게 표시합니다. `초기화`로 전체 층으로 돌아갑니다.
- 다른 현장의 안내도도 한글·영문 OCR을 두 가지 이미지 처리로 읽고 일치 여부를 비교합니다. 자동 연결은 정확도를 보장하지 않으므로 실제 자료로 검토해야 합니다. 안내도에 MRI실 등 상세실이 표기되지 않았다면 세부 안내도를 등록해야 합니다. 최초 분석에는 엔진·언어 데이터 다운로드가 필요하며 이미지는 서버에 업로드하지 않습니다.

## GitHub Pages의 데이터

공개 사이트에는 공개 안내도와 이미지에서 읽은 장소 정보만 포함하며, 설치 단말 목록은 비어 있습니다. 내부 IP, 스위치 정보, 제공받은 엑셀, 현장 사진은 저장소와 배포본에서 제외합니다. 예시 장소를 설치 단말로 표시하던 이전 데이터도 업데이트 때 제거합니다.

실제 목록은 사이트에서 `엑셀 가져오기`로 선택합니다. 파일 읽기, 자동 매칭과 IP 표시, 저장은 사용자의 브라우저 안에서 처리합니다. 브라우저별 데이터는 다른 방문자와 공유되지 않습니다. 사진이 포함된 기존 현장 백업 JSON도 브라우저에서 불러올 수 있습니다.

## 실행

Node.js 20.19 이상 또는 22.12 이상을 사용합니다.

```sh
npm install
npm run dev
```

터미널에 표시된 `http://127.0.0.1:5173` 주소를 엽니다. 설치 장소, IP, 사진은 브라우저에서 처리하며 외부 서버에 전송하지 않습니다. 개발 서버는 루프백 주소에서만 실행됩니다.

## 첫 현장 데이터

이 작업 공간에는 `local-data/site.json`, `local-data/maps/`, `local-data/photos/`가 준비되어 있습니다. 셋톱박스 52대와 별도 사진 시트의 미디어월 1건을 구분합니다. 감마나이프센터 1대는 건물·층을 미확정으로 유지합니다.

원본 XLSX를 다시 준비하려면 아래 명령에 파일 경로를 전달합니다. 파이썬 표준 라이브러리와 curl만 사용합니다.

```sh
python3 scripts/prepare_site.py '/절대/경로/단말목록.xlsx'
```

이 명령은 XLSX를 로컬에서 읽고, 병원의 공개 안내도만 다운로드합니다. XLSX 내용은 업로드하지 않습니다. 기존 `local-data`를 갱신하므로 브라우저에서 수정한 내용은 먼저 내보내기 하세요. 이미 저장된 브라우저 현장은 자동으로 덮어쓰지 않습니다.

## 사용 순서

1. 건물과 층을 선택하거나 단말명·설치 장소·IP로 검색합니다.
2. 단말을 선택하면 설치 정보와 해당 장소 그룹의 참고 사진을 표시합니다.
3. `검토 필요`에서 원본 안내도와 후보를 대조하고 연결합니다. 실제 설치 지점은 `설치 위치 직접 지정`으로 별도로 표시합니다.
4. 평면·입체 보기의 장소 영역을 클릭하면 해당 영역을 중심으로 이동합니다. 위치 미지정 항목도 목록에서 계속 확인할 수 있습니다.
5. 현장 관리에서 새 현장·건물·층을 추가하고 PNG/JPEG/WebP 안내도를 등록합니다. 이미지가 없는 층은 미등록 상태로 표시합니다.
6. 엑셀 가져오기에서 시트, 헤더 행, 각 열의 의미를 선택합니다. 선택한 시트로 **현재 현장의 단말 목록을 교체**합니다. 단말명·층·설치 장소가 모두 같은 항목만 기존 사진과 직접 위치를 유지합니다. 사진 시트는 일반 가져오기에서 자동 분석하지 않습니다.
7. 현장 내보내기는 안내도·사진을 포함한 JSON 파일을 만듭니다. 다른 브라우저에서 현장 불러오기로 복원할 수 있습니다.

변경 사항은 해당 브라우저의 IndexedDB에 자동 저장됩니다. 브라우저 데이터 삭제나 다른 기기에서는 유지되지 않으므로 내보낸 현장 파일을 백업으로 사용하세요. 서버 계정·다중 사용자 동기화·실시간 단말 접속 상태 점검은 이 버전에 포함되지 않습니다.

## 자료의 의미

- 공개 안내도: 
- 공개 구조화 목록: 
- 전체 건물의 층을 가져옵니다. 공개 안내도 일부는 특정 부서가 강조된 이미지입니다. 강조된 색은 단말 위치를 의미하지 않습니다.
- 공개 사이트의 부서 명칭·배치와 현장 엑셀의 내용이 다를 수 있습니다. 지도 위치는 현장 확인 후 지정해야 합니다.
- 엑셀 사진은 시트의 설치 장소 행에 연결했습니다. 같은 장소의 여러 단말에는 같은 그룹 사진을 표시하며 개별 단말 식별을 확정하지 않습니다.
- 층 쌓아 보기는 이미지 평면을 입체적으로 배치하는 2.5D 표현입니다. 실제 건물의 벽·높이·정확한 축척을 모델링하지 않습니다.

## 파일과 빌드

```sh
npm test
npm run build
```

- `src/components/`: 화면 구성
- `src/lib/model.js`: 현장 데이터 형식과 검증
- `src/lib/workbook.js`: XLSX 읽기와 열 연결
- `src/lib/storage.js`: 브라우저 저장과 이미지 포함 내보내기
- `src/lib/autoMap.js`: 이미지 식별자·방 번호·후보를 검증하는 장소 연결과 현장 규칙
- `src/lib/imageAnalysis.js`: 브라우저 OCR과 장소 영역 인식
- `public/catalog/`: 공개 안내도·장소 정보만 포함한 배포용 데이터
- `scripts/prepare_site.py`: 초기 현장·사진 준비
- `tests/`: 병합 셀 처리, 층 매칭, 데이터 검증 테스트

`local-data/`는 Git에서 제외되고 개발 서버에서만 제공됩니다. `dist/` 빌드 결과에 병원의 내부 IP와 사진을 넣지 않습니다.

## GitHub Pages 배포

이 저장소의 `main`은 소스, `gh-pages`는 공개 빌드 결과만 저장합니다. Pages의 게시 원본은 `gh-pages` 브랜치의 `/`입니다.

```sh
npm test
npm run deploy:pages
```

배포 스크립트는 `origin` 저장소 이름에 맞는 Vite 기본 경로로 빌드한 뒤 `gh-pages`에 일반 push합니다. 기존 기록을 강제로 덮어쓰지 않습니다. GitHub 저장소 쓰기 권한이 있는 인증이 필요합니다.

공개 카탈로그만 갱신하려면 `node scripts/build-public-catalog.mjs`를 실행합니다. 로컬 원본 XLSX를 읽지 않고 공식 사이트의 공개 정보만 사용합니다. macOS에서는 `swift scripts/read-plan-labels.swift <안내도 이미지...>`로 공개 안내도의 글자 좌표를 다시 읽을 수 있습니다.
